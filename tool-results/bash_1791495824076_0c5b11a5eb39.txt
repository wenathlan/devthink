## 3. REGRAS DE DESIGN (skills) — mandamentos práticos para o sol.css

### 3.1 Contexto do tema (doc B + design-premium)
- **Um único stylesheet**: "dentro do tema existe um único CSS, o index.css, com nome personalizável (index.css, sol.css ou o nome do tema); nunca style.css, nunca um CSS por componente". "os estilos vivem no index.css do tema, nunca em arquivo por componente". Nada de `.styles.ts` por página.
- **Tema Sol (default)**: tokens `#0B0806` (base) / `#F59E0B` (acento âmbar) / `#FFFBEB` (claro) + variantes EMBER/TANGERINE · Cyber · Nature · Ocean · Obsidian. Dark-first com rampa própria. Troca via **classe `theme-*` no `<html>` persistida em localStorage**.
- **Assinatura cromática da família**: "cerca de 78% das variantes usam papel creme #F4F3ED com tolerância de 3 pontos, tinta quase-preta e lime ácido #C8F542" — regra 90/10 (1 cor sinal carrega 90% do chrome, neutros carregam a massa).
- **Estética pedida (citação do dono)**: "a mistura de chrome, brave, trello... windows 10 e 11 e apple silicon — a barra flutuante de ícones que expande ao clique"; "liquid glass, acrylic mica, dark claymorphism, cantos de onda 28px, omnibox estilo browser, shelves estilo Netflix"; "respiração Windows 11 (cantos 8-10px, acrílico/mica sutil, elevação 2 níveis, focus ring)". Constantes da casa: "as constantes da casa são saddle 24/14 e liquidglass.css com blur(50px) e saturate(200%)".

### 3.2 Vendor prefixes (como aplicar)
- `backdrop-filter` SEMPRE com prefixo: as receitas e o skeleton de liquid glass usam `-webkit-backdrop-filter: blur(24px) saturate(180%) contrast(1.05);` junto do padrão. Todo vidro do sol.css leva o par.
- `mask`/`mask-composite` com prefixo para bordas-gradiente e recortes: `-webkit-mask: linear-gradient(#000 0 0) content-box, linear-gradient(#000 0 0); -webkit-mask-composite: xor; mask-composite: exclude;` (receita `.grad-ring`). Máscaras de notch/scallop idem: `-webkit-mask: radial-gradient(...)` com `-webkit-mask-size`.
- `@property --p { syntax:'<number>'; ... }` para gauges animáveis (transição de custom property tipada).
- Fallback obrigatório: "backdrop-filter fallback" e `@media (prefers-reduced-transparency: reduce)` com fundo sólido (`rgb(255 255 255 / .96)`, sem blur) — vidro nunca é o único portador de legibilidade ("legibility demands ≥35% blur").

### 3.3 Z-index / camadas (disciplina)
- **Z-bands oficiais**: `0` atmosfera · `10` conteúdo · `20` consoles/flutuantes · `50` barra fixa ("up to 1000 fine-grained"). UI doc: dropdown 50 / sticky 100 / modal 200 / toast 300 / tooltip 400.
- "aglutinação + z-index caótico" é item da ban list; taste-skill: "NEVER spam arbitrary z-50 or z-10... Document the z-index scale in a project constants file" — ou seja, o sol.css declara a escala em custom properties/comentário e só usa para contextos sistêmicos (navbar, modal, overlay, grão).
- Camadas internas do ícone animado (feature Sol): pilha por index — glifo (topo) / anel (meio) / fundo externo (base); halo frosted é outer-ring only, sempre ATRÁS do contorno gradiente; `::after` de halo usa `z-index:-1`.
- Grão/noise em pseudo-elemento `fixed inset-0 pointer-events-none` (nunca em container que rola).

### 3.4 Variáveis CSS e tokens
- Tokens em **OKLCH com 3 tiers** (primitivos → semânticos → por componente); papéis semânticos: tinta/papel/campo/sinal/alerta/atenuado/linha/profundidade; **estados derivam via `color-mix(in oklch, ...)`**, nunca alpha inventado. Variáveis-padrão das receitas: `--sig` (acento), `--page`, `--ink`, `--r` (raio), `--ease: cubic-bezier(.2,.8,.2,1)`, `--spring: cubic-bezier(.2,1.2,.4,1)`, `--spring-soft: cubic-bezier(.34,1.56,.64,1)`.
- "Use CSS variables for consistency" (frontend-design); dark mode tem rampa própria; nunca `#000000` puro nem `#FFFFFF` puro (off-black tipo zinc-950, off-white).
- Nada hardcodado: tema vem do DB; "zero magic number em CSS" — constantes de geometria da casa viram tokens (ex.: BOX_CORNER_RADIUS 24, SADDLE_CONCAVE_RADIUS 14, TAB_HEIGHT 40).

### 3.5 Tipografia e fluid type
- **Tríade** display 700-900 (Syne, Clash Display, Outfit ExtraBold, Space Grotesk...) + leitura 400-500 (Outfit, Satoshi, Instrument Sans; line-height 1.6) + detalhe 200-300 SÓ em micro-labels; máx 2 famílias + 1 script; **Inter/Roboto/system-ui BANIDOS como identidade**; fonte self-host com `@fontsource`, "nunca Google Fonts link"; "declared ≠ shipped" (a fonte precisa viajar no build).
- Escala 12-72px; herói 64-96px (mega até 260px); razão 1.25-1.333; **`clamp()` fluid**; tracking −2% a −5% em display, +4% a +12% em micro-labels caps; mono em labels 8-11px com tracking 0.08-0.2em; `text-wrap: balance` (títulos) / `pretty` (parágrafos); `tabular-nums` em stats 700 de 72-96px; 45-75ch de medida.

### 3.8 Motion / timing
- Micro 120-250ms (≤200ms na doutrina geral); entradas 400-800ms com **stagger 60-90ms** (entrada padrão riseIn 24→0px em 0,6s com delays .05/.18/.31/.44s); loops ambientes 8-30s (≥4s); demos ≤9s; UI feedback <300ms.
- Easings: base `cubic-bezier(.2,.8,.2,1)`; M3 `cubic-bezier(0.2,0,0,1)`; springs `cubic-bezier(.2,1.2,.4,1)` 300-560ms; toggle `cubic-bezier(.34,1.56,.64,1)` 300ms; **NUNCA linear em micro; NUNCA ease-in em entrada; NUNCA bounce fora de contexto candy; entrada decelerate, saída accelerate, ciclo spring**.
- Entrar de `scale(.9-.95) + opacity`, **nunca `scale(0)`**; pisos: modal 0.96 / menu 0.97 / tooltip 0.98; press `:active` scale .94-.98 (ou translateY(-1px)); lift −4px com sombra.
- Orçamento: 1 idle herói + ≤2 secundários por página; animar a FUNÇÃO (toggle/contador/cursor), nunca o pano de fundo; interrupções só em transform/opacity.
- **`prefers-reduced-motion` obrigatório**: todo motion ambiente dentro de `@media not (prefers-reduced-motion)`; WCAG 2.2.2 (pausa para motion >5s) e 2.3.1 (máx 3 flashes/s); motion nunca é o único portador de informação.
