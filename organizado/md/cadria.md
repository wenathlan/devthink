# cadria

## Objective

Cadria is the video and image player, editor and studio of the family — it absorbs the retired player and editor apps and houses the versawase engine (image, video, animation and 3D) at its root. It imports the audio analysis engine from debonair and the gateway, AI and workflow surfaces from the OS, and publishes the versawase engine as the family library every 3D consumer (the FPS platform among them) imports.

## Features

- Video and image player — a formats table drives playback of the media the site serves.
- Studio — the studio shell docks creative anchors, controls, source rail, readout, stage art and a live visualization panel.
- Timeline editor — full edit algebra over tracks and items with media handles.
- Gallery — the asset gallery view of the studio's projects.
- Image studio — pure pixel operations (brightness, contrast, saturation and siblings) over image data.
- Generation pipeline — the audio-to-image generation data layer with analyses and generation records behind the gateway agent.
- Real byte encoders — PNG, GIF89a, video and webm encoders ship real decodable bytes, never mock buffers.
- Compositor — a fragment effect library with film and optics vocabulary plus a pass compiler.
- 3D engine — mesh geometry, scene composition, camera and render over the shared engine.
- Animation scheduler — frame rates, ticks and timecodes drive deterministic scheduling.
- Synthesis wave — composition, motion, palette and texture synthesis for the audio-to-image studio.
- Transcode engine — transcode plans between media formats with size estimates.
- Media probe — probes media inputs for the pipeline.
- Blend and color — blend modes, color conversion and masks over the pixel engine.
- Easing curves — duration-independent temporal easing of keyframe segments.
- Library face — the engine publishes one subpath per module so siblings import the 3D, animation and render concerns through the package instead of reaching across folders.

## 3D/Video

- Engine consolidation — the 3D, animation, composition, generation, render, scheduler, shader and slice domains answer one keyed engine seat with every export preserved.
- Real encoders — complete PNG streams (signature, headers, image data, end), complete GIF89a streams and the video/webm byte lanes.
- Fragment effects — named effects drawn from film and optics vocabulary (lap dissolve, raccord, halation) compiled into draw passes.
- Edit algebra — overwrite, insert, lift, extract, split, edge trims, roll, slip and slide, each limited by media handles.
- Timecode system — ticks per second, frame rates, clamping, snapping and formatted timecodes.
- Transcode plans — unpack, recompress, seal plans between formats with honest same-format no-ops and compressed-size estimates.
- Visualization — image inputs and mesh geometry feed the render and visualization surface.

## Interactions

- Route tree — intro, onboarding, home, player, studio, edit, gallery, settings and the 404 page.
- Intro suite — splash, capabilities, demo and footer frames before the platform chrome.
- Studio widgets — controls, export row, parts, readout, source rail, stage art and visualization panel.
- Entry gates — home entry gate and shell entry gate resolve the first-run flow before the landing.
- Shell — brand mark and cadria mark, empty states with real actions, page rail and family foot.
- Settings — theme and preference surfaces shared with the family law.

## Data

- Projects, assets and render jobs ride the same SQLite database the schema describes; the catalog accessor serves content rows over HTTPS with the in-memory seed fallback.
- Generation records — analyses and generations tables with parameterized accessors behind the gateway seam.
- Onboarding flags and label rows persist through the shared storage lane.

## Engine role

3D and video engine of the family: every render, animation and 3D concern of the siblings answers through the published versawase library; the FPS platform renders at the pre-compiled stage pinned to this engine.
