## Channel publication gates (1.1.87)

The publishing pipeline of 1.1.87 gates every channel on the assembled artifact set: a channel job never runs before the assemble job produced the artifacts it publishes, and the attestation job never runs before every channel job answered. The registry channels (GitHub Packages npm, npmjs, maven, nuget and the container registry) publish only after the `release-approval` environment protection approves the run — the environment carries the operator's reviewers, so nothing auto-publishes when the protection is configured. Every publish step retries inside a bounded policy of three attempts with a growing pause between them, so a transient registry failure never aborts a release silently and never retries forever.

The digest gate pins the pushed container image: the digest job inspects the pushed reference, recomputes the digest, writes the reference, digest and json files and refuses when the stable channel alias tracks another image than the version tag. The sbom gate covers every release artifact in the cyclonedx inventory with the sha256 of each, the checksums gate covers the complete release set in `SHA256SUMS.txt`, and the artifact manifest gate lists every artifact with its name, byte size, checksum and channels before the manifest itself joins the set. The draft release gate gathers every artifact into a draft first; the verification step downloads every draft asset back, verifies every checksum, and only the verified release publishes. The rollback gate freezes the previous release artifact set through its immutable tag with the pinned checksums of the previous artifact manifest, so a rollback restores the exact previous set instead of a mutable latest.
