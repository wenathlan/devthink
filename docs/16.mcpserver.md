# The mcp server mode

The 1.1.84 family exposes the devthink engine as a model context protocol server: any mcp client the user launches can list the toolcatalog, read the resourceexpose surfaces, render the promptexpose templates and call the reviewed tools over the stdioserve and httpserve transports. Consent stays in the loop everywhere: the sensitive tools block until the human approval gate answers (the gate renders in the sidepanel with the caller and its intent), the consent requirements refuse execution when the grant is missing, every tool call writes an audit entry with the caller, the tool and the outcome, and the server degrades to read only tools when no origin grant exists.

## The server and the transports

The `devthink serve` cli command starts mcpmode (the flags: `--stdio` speaks json rpc over stdin and stdout with newline delimited frames, `--http [port]` speaks streamable http on a localhost bind, `--port` names the http port, `--cert`/`--key` enable tls when the user provides a certificate, `--degraded` starts read only, and both transports can run at the same time). The httpserve transport binds to localhost by default and requires the auth handshake (the token exchange of the servercontract pairing family) for any non localhost connection; the stdioserve transport works with the local clients the user launches. The shutdown drains the in flight calls before exit, the health resource reports the version and the uptime, and the server events stream the plan progress to the subscribed clients through the servercontract envelopes.

## The toolcatalog

The toolcatalog maps the action kind catalog to mcp tools: every tool carries its json schema inputs, its domain namespace (browser, workflow, memory, system), its version, its consent requirement and its risk class in the metadata, and its description follows the openapi style field layout. The browser domain exposes the snapshot, extract, readtext, readtable, readlinks, a11ytree, observe, tablist and windowlist read tools beside the gated interaction and sensitive tools; the workflow domain exposes the plan proposal tool with the full grammar and the review gate tool that waits for the human approval; the memory domain exposes the session and memory tools; and the system domain exposes the health and the tool mocks. The sensitive tools (the click, type, submit, payment and credential classes) block until the approval gate answers — the consent metadata of every tool must match the policy grading exactly, and a tool the current grants do not cover never exposes.

## The resources and the prompts

The resourceexpose surface publishes the page state, the plan, the audit trail, the session record and the health as mcp resources with subscription support (the change notifications deliver as json rpc frames to the subscribed clients). The promptexpose surface publishes the prompt template library as mcp prompts with the walkthrough templates for the common tasks.

## Client configuration

Any standard mcp host configures devthink as a command server over stdio (`devthink serve --stdio`) or as an http server on the localhost port; the client metadata records its name and version for the audit trail, the client allowlist restricts which clients may connect, the rate limiting caps the requests per client, the session tokens pair a client with one extension session, and multiple concurrent clients hold isolated sessions.

## The native event streams (1.1.85)

The native host bridge streams its transport events to subscribed mcp clients: every native surface call emits a `native/call` notification with the surface, the call class, the outcome and the correlation id — never a payload — so a subscribed client follows the native transport exactly as it follows the tool calls and the plan progress. The native frames themselves reuse the servercontract envelopes (see docs/14.servercontract.md for the native frame envelope reference), the wsbridge advertises its localhost port and per session token to the extension over the native port, and the consent gates, the kill switch and the escape hatch of docs/17.nativebridge.md stay in front of every streamed event.
