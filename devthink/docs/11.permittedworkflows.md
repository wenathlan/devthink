# Permitted Repository Root and Workflow Audit

This report was generated by reading every root file and every GitHub workflow file, one file at a time, in the four repositories the user authorized for comparison. The report records file inventory, hashes and workflow metadata; it intentionally does not copy implementation or workflow source into Devthink.

The observed patterns will be adapted only where they fit a browser-extension package and its metadata. A detected publishing target does not mean the target is compatible, configured or authorized for this project.

## Consolidation decision for Devthink 1.1.1

The reference repositories use many narrowly named workflows, including workflows for desktop, mobile, Pages, RubyGems and virtual-machine products. Devthink is a TypeScript library plus Chromium extension, so those product-specific pipelines are intentionally not copied. The compatible controls are consolidated by responsibility rather than duplicated by destination: `verify.yml` owns integration validation; `security.yml` owns static, dependency, secret and SBOM checks; `maintenance.yml` owns reviewable dependency, runtime, action and generated-metadata updates; and `release.yml` owns release artifacts plus all compatible publication destinations. This preserves the security, digest, artifact, registry and update capabilities found in the authorized references without claiming unsupported native, mobile, VM or language-runtime products.
