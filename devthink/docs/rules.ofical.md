# the ofical rules — the canonical mapping of the owner rule file

the mandatory rules of the devthink family operation, mapped by category from the owner rule file, merged and deduplicated. the owner statements are the source, session 7 prevails. every rule below is sourced, nothing is invented. the format obeys the writing rules themselves: dot hierarchy, lowercase, english, zero emoji, links only in the last paragraph.

## objective

. build the devthink platform end to end: the virtual operating system of the internet, the superplatform that carries every application the person needs.
. the focus of the current operation is the chat application first: fully functional, it opens the sandbox and executes the sandbox, with the design redefined to the reference standard and the presentation icon redefined with it.
. one application works fully at a time, devthink first, then the sub apps.
. something is put online immediately, before anything else is finished: a plain blank white page in english on the main domain, then the policy page and the terms page.
. authentication stays on the own self hosted infrastructure, never supabase.
. later the repository builds to cloudflare, netlify and vercel and serves the full domain, so no current choice may close that path.
. the configuration of external platforms is done through the owner real logged in brave browser, because the owner cannot configure those screens.

## writing and format

. everything lowercase, titles included, only code, file names and versions keep their own case.
. dot hierarchy only: point, subpoint, subpoint of the subpoint, no hyphen as marker, no numbered bullets, hyphen becomes dot in prose.
. one idea per sentence, clear, objective, progressive, connected and cohesive, impeccable spelling, grammar and punctuation, third person in all technical prose.
. one theme per sentence and paragraph, the subject changes after the punctuation, never stacking subjects.
. paragraphs and tree lines spaced, a blank line between paragraphs, nothing glued, nothing telegraphic.
. duplicate words, duplicate senses and duplicate logics merge into one statement, one concept in one place, no synonym pair for the same thing, no contradiction.
. zero emoji anywhere, zero source citation, no line or origin numbering inside the text.
. markdown tables are born perfect with header, separator and padded cells, library, engine and icon lists go in code boxes, never in tables.
. sections end with a table, rules above, tree drawings below, in the template and the example.
. retired infrastructure is kept marked as previous plan, never struck, never deleted, never blank.
. all links, paths and commands live only in the last paragraph, the to visit list, and the body cites them by position, for example the second link of the last paragraph.

## design

. the standard is windows 11: same look, interactions, animations, micro interactions, icons and quality, elevated to professional saas refinement for apple silicon, as shown in the index.html reference, in trylle and in the competitor references.
. the interface design is the mix of chrome, brave, trello, windows 10 and 11 and apple silicon, with the floating icon bar that expands on click, and a design below that standard is rebuilt, not patched.
. the style is clean, minimalist, premium, professional and objective, no extra words, no extra elements, zero vibe code, animated icons never emoji.
. the lock screen and the authentication screen are identical to windows, and mouse, keyboard and button interaction is identical to windows 11 and to the competitors.
. every application must match the index.html quality bar, apps below it are rebuilt, not patched.
. one single design track serves everything, only the presentation screen changes per platform: web, tv, binary, extension, and on web the platform screens exist but stay hidden, enabled in settings as default, normal or custom mode, and they keep working.
. responsiveness, dpi and xdpi are correct on every presentation screen, the same build changes only aspect ratio, dpi and responsiveness, portrait is mobile, landscape is tv or desktop, wrappers only package.
. onboarding is frame by frame adapted per app, login skippable via the os, sequence logo, login, entry, nav.
. the icon of an application is animated from within: the gradient moves inside the glyph, each layer stacked with its own index, the glyph on top, the ring below, the outer background at the bottom.
. the internal reference is the desktop os in the browser with thirty view modes and about 240 widgets, radius 8 windows, blurred topbar and 27 keyframes per icon.
. the design foundation is the absolute authority: oklch color, three tier tokens, one signal accent per page, one gradient per page, radius ladder, micro motion 150 to 200ms, entries 400 to 800ms with stagger, the thirteen laws per page, the ban lists and the zero ai tells gate.
. design references live in neoimg, competitor and site references live in temp, clone them whenever in doubt about logic or references.

## chat application

. the chat is the urgent item: fully functional, it opens the sandbox and executes the sandbox, the redesign of everything, all sub apps working end to end.
. the chat design follows the reference grammar of zcode, synara and t3code on the windows chrome, taking features from the competitors: zcode, synara, t3code, openai and the others in the temp references.
. the chat presentation icon is redefined with the design, the animated icon with the internal gradient, never an emoji.
. every user message is understood by 7 independent sub agents, an eighth sub agent makes the final summary, then the output is produced.
. when the user edits a message the running work is never interrupted: a checkpoint is marked, a new session number is opened, a parallel clone runs.
. a finished run sends its checkpoint and result to the next session, an unfinished run waits and passes its checkpoint forward, the chain never stops.
. all checkpoints stay in one context and are merged at the end, the last edit prevails, no detail of an earlier checkpoint is ever lost, so the thread of context is never lost.
. the final agent confirms that every branch finished before answering, and checkpoints include screenshots and real time status updates.
. the conversation is born with a sandbox: space id, sandbox id, session id and message id provisioned automatically, chat and agent are synonyms, the correct separation is conversation and vm.
. the chat embeds the xterm terminal with process monitor, the headless browser with stream and network inspector, and the monaco editor with diffs.
. an approval modal with diff, command and risk levels, allow once, allow always or deny, precedes every sensitive action, and the emergency kill switch kills vm processes and cancels api calls with checkpoint restore.
. automatic execution is blocked by default, scope per site, stop and revocation always available, control before action.
. the composer carries the stacked well grammar, the avatarless timeline, the draft chips, the reasoning expander owning the violet, the day separators and the labeled controls of the references.

## apps and identities

. devthink is the os and superplatform, it engulfs devthinkos, cli desktop, soflowx, akash, extension, gateway and maene and embeds owni, it has its own browser named devthink, 35 native pages in theme and news as a page, it creates no video, image, 3d or audio logic and imports from published libraries, and it runs the same interface everywhere, cli equals web equals tv.
. saddle is the sandbox and vm runner, virtualization only, complete sandbox and runner of any market sandbox, no browser, no gateway, no os features, it brings 3 bases max, balanced and lite, the oses android, grapheneos, linux, omarchy and windows, the arches arm64 and amd64, its own vgpu and vcpu, and it manages the virtual hardware the domains use.
. debonair is audio and daw, creation of audio and music, isolated app with its own marketing name, it houses the katexis engine at the root.
. cadria is video and image, player, editor and studio, it absorbs iukka and create, it houses the versawase engine at the root.
. stealhead is the first person shooter game, it imports versawase and audio via library, no own engine file, and loads only game logic, match, ranking, weapons and world, shipping pre compiled.
. argan is dns and the network library of the system, zones, records, dnssec and handshake, and every site uses the same unified db.
. getry is the deployable gateway, the inference of the network with the devthink meta model masking the real models, and as deployable clone it raises copies of itself to sustain concurrency, always with free tag models.
. ansi art is editor, gallery and conversion, 21 loose ts logics at the root and own pages, soochimp features absorbed, the engine appears as ansiart.ts embedded in devthink when it is not its own app.
. vault is the storage library of the platform, all storage lives in it and only in it, and the other apps import the published library instead of reimplementing.
. forge runs only, foundry runs and stores, and with getry they are the deployable site clones materializing the site roles of the network, they come from saddle, are not new apps, and have no distribution at all, they exist only as sites.
. each app cares for one thing and distributes it as library, and devthink imports instead of duplicating: image or video imports cadria, audio imports debonair, sandbox imports saddle, storage imports vault, logic is never duplicated and each family of features has one single house.
. discord, trello, github, gitlab and supabase features become apps, and pulled apps carry the tag of who pulled them, creator, ai or community.
. doo is the universal system ai, and the person may create, train and connect own ai with mcp, api and gateway and build sites with sandbox and preview.
. removed apps are forbidden to return, their features live absorbed in the roster.

## structure

. repository root only with app and mode folders, plus docs, tests, forjas and loose files.
. flat: no src in the house, no folder inside folder, no globals by category, no lib, hooks or components folders.
. folder equals page equals app, with everything of it inside, page config is app config.
. every app has its own docs and tests, with scripts in tests scripts, it references, it does not copy.
. one manifesto per language at the app root, version in lockstep, one lock only.
. github at the repository root, workflows self contained, one per responsibility, and forja mirrors repeat github, for example gitlab and forgejo.
. auxiliary scripts of the family live inside devthink in tests scripts, standardized in typescript, no scripts folder at the monorepo root.
. nothing is deleted, duplicates keep a numeric suffix.
. no ui, assets, public, dist, data or db folders in the tree, compilation and artifacts stay at the owner root or outside the repo, and only icon and favicon exist as assets.
. all apps have the same structure, no file at an app root that does not exist in the others, and the only variation is the deploy copies inside the theme folder beside app.tsx.
. the global anchor app.tsx lives inside the first theme folder, beside index.css and index.html, the app root loads only loose ts logics, loose configs, docs and tests.
. the page is a folder with its own name: the page tsx subanchor, the tsx components loose in the folder and ts helpers when needed, no styles, types or test tsx file per page.
. the theme is the folder and there is no default folder, the theme folder is sol, and the old site folder stops existing in every app with its content absorbed into sol with zero loss.
. n themes equal n complete folders, and later themes carry only page folders, not the framework config that already lives in sol.
. inside the theme there is one single css, index.css with customizable name, and the only html is index.html at the theme root.
. no 404 html, notfound is a tsx component and the build workflow resolves the fallback at deploy time.
. the subanchor imports the subroute anchors and each subroute imports its own components, up to one hundred per page, and adding a component is adding a line in the subanchor.
. general logic, authentication, interaction and data, stays at the app root in ts, interface logic lives inside sol embedded in ts or tsx.

## code

. loose ts logics at the app root, the interface pulls from the root, the root never pulls from the interface, the interface never pulls from the interface.
. correlated logics together in hierarchical blocks, one file one responsibility, up to about 300 logics per file.
. typescript first, runtime native before external package, the app is born a multi mode library.
. zero js in the interface: only ts, tsx, css and html, explicit ts in relative imports, no enum and no namespace.
. no main: app.tsx self mounts with embedded routing inside the theme, covering themes and 404.
. nothing is hardcoded: the only hardcoded names are doo and devthink, the db populates the content, the code is the engine and the db is the living config, components read through typed accessors, host and port are drawn and locked per session, never localhost.
. english in code and jsdoc, no emoji, trackable try and catch, file names are lowercase without underscore or hyphen, short unique keywords, composed names use dot, never hyphen, except framework config files which keep their convention.
. only the entry logic migrates from the theme to the root, like gateway.ts.
. typescript strict, any forbidden, ts-ignore forbidden, biome the standard formatter and linter, conventional commits enforced.
. every component carries two logics: the animation one and the one that makes the micro interaction work, a component is a pre output of a feature.
. a new component or feature is born only from a button mapped in the screen catalog or from a skill adopted in the catalog, the catalogs are the permanent index.

## engines and libraries

. the engine lives in one app, the others import the published library, no circular dependency.
. universal library: any project imports and only configures baseurl, models and keys, engines are libraries with zero consumer data inside and typed exported api.
. more than 100 engines in total, no limit of engine, library, framework or package as long as node.js orchestrates behind, duplicates between categories resolve at adoption with one entry per concept.
. ai and icon libraries go in code boxes, by category, without limit, the central icon repository serves all apps with one family per project, including the official microsoft icons fluent2 and winui3.
. per job rule: script or one shot sandbox is bun, network service or production is node lts, transform is swc or babel, bundle is esbuild for dev or webpack for heavy, foreign binary is saddle sandbox or wasm.
. the engine budget of the manifest carries 15 engines working, node the orchestrator.

## sandbox modalities

. saddle concentrates more than ten modalities toward thirty, and none touches the person hardware, all run on runner sites over mime types and https, the person chooses none, the platform resolves the join of all as the nuclear modality.
. site is already sandbox, account is sandbox, about 50gb per plan.
. the modalities: complete virtual with driver, cpu, gpu and memory in three profiles, universal runner of any sandbox and binary, node packages, docker container hardened, ghcr container immutable with uuid instance, microvm per workflow with clean rootfs and the mesa graphics stack, browser and virtual browser opt in, mobile with capacitor and termux, confidential with attestation, qemu and firecracker, pod, local opt in with consent and v8 isolates serverless, wasm and wasi, vfs born from prisma, git and db, and cdn of about 45 cdns fetched inside the sandbox via vfs, never in the person browser.

## data and infrastructure

. drizzle orm and better sqlite3 execute, prisma is only declarative schema inside the theme, no sql file in the repo.
. the db is unified between sites and apps, never committed, master plus shard per account.
. blobs are never in the db: chunks with sha 256, compression and catalog, automatic reuse.
. sites are replicable with write quorum n/2+1, read any of n, idempotent daily reconciliation.
. the memory tiers: n1 ram in sharedarraybuffer microseconds never persisting secrets, n2 opfs with sqlite surviving reload with bm25 and hnsw indexes, n3 github releases, gitlab lfs, cdn and free s3 durable with 2gb per asset, crypto shred propagates across tiers.
. the vfs pager uses 64 bit bigint, path sandbox mnt data, quota 50gb, zstd default, aes 256 gcm at rest, snapshot vdr snap atomic.
. apps live in the db: a binary upload with rootfs is installed through the vfs sandbox modalities, artifacts are set in the db, and the app runs by the saddle engines of virtual memory, virtual ram and virtual storage offered between sites.
. every upload passes the yml pipeline of the site itself: it converts and optimizes into chunks, packs in tar.xz, writes to the site db and fires the mimetypes api so the family sites sync backup.
. the db is not readable or exportable, no user reaches the database, only those registered inside it.
. one login across the family sites, the dbs talk over https, same storage, callbacks and identity.

## zero touch

. the interface never writes in the browser: no indexeddb, localforage or localstorage, and the offline answer of the static build comes from seed in memory, never from browser storage.
. the interface never uses visitor gpu, cpu, camera or geolocation and never compiles on anyone machine, the person machine only loads the interface.
. each site becomes a sandbox when the person enters with id, and the modalities run on our domains over https, mimetype and api.
. nothing touches the person hardware, all virtual: engini virtual is the doctrine.

## build, deploy and release

. build, test and publish are typescript end to end, js only as emit on publish, bun runs directly.
. build, test and hash only on the github computers, the agent generates no binary and runs no authoritative battery, light local gates for sanity.
. workflows are yml declarative, linear, hierarchical with triggers, matrix, caches, artifacts and automatic release on manifest, ignore or changelog change, assets per app, single version.
. release by bump: tag, per app zips, sha256sums, release notes from the changelog, and the next forms exist only as zips in the release assets, never as folders in the repository.
. official compression is tar.xz level 9 plus brotli one over the other, applied via yml over the git objects, zip stays only where the platform requires it.
. every app ships to all registries: npm, gh npm, ghcr, nuget and maven, engines travel as npm and maven packages with the spring boot module.
. the same tree serves every deploy target, static without functions, deploy copies live inside the theme folder, and the isO distribution and the wasm distribution travel as release lanes.
. version in lockstep across all envelopes, the gate reads package.json, never a literal, one lock per manifest, npm ci never install.
. actions pinned by version tag, never sha, no hardcoded hash, the hash is generated at build and travels in the assets.

## git and ci

. commits always in the owner identity, conventional commits, one action per commit.
. main branch protected, prs and branches archived, only main remains.
. one workflow per responsibility, dependabot in the github folder never in workflows, secrets never in if, the publishes run by workflow_run pointing at the real name.
. the bump loop until all green: fix at the root, bump, push, monitor, repeat, every bug one bump, immutable tags.
. zero zero zero dashboards as the done criterion, collateral red runs deleted.
. every action of more than 100 steps starts with a checklist of about 100 items, organized in waves, adapted to context, and the system itself follows the same rule.

## security

. secrets never in code, env gitignored, rotation, aes 256 gcm for tokens in db, node crypto for randomness, never math random.
. tls 1.3, hsts preload, strict csp, cors only the family domains.
. passwords argon2id, session jwt with rotating jti, oauth with state and pkce, pii dedicated with access log, right to erasure with crypto shred cascade.
. rate limit public and authenticated, sandbox egress with allowlist, backend denylist of sources and databases, no captcha anywhere on the platform.
. the kill switch always available, consent gates of three steps, deny by default, the ai never participates in authentication.
. exposed credential cataloged for rotation, never replicated.

## operation

. two phases only: analysis first, execution second, never mixed, a phase closes before the next opens.
. fixed step order: delete everything, read files, create authentication, run full analysis, create documents, execute.
. date first: consult the date and use the best pattern and version of that date at each step.
. read only through the bash terminal, sed segments of line ranges x to y, hierarchical and segmented, index first, details after, very large files in segments of 1000 to 4000 lines with grep to index markers before directed reading, never the whole file at once.
. the read tool is never used, by the agent or by any sub agent, forbidden tools are read, chaos tools and results tools.
. delegation is open, from zero to 300 sub agents in parallel, any number of waves, every wave hierarchical and objective, with verification each wave.
. delegate sub agents before executing inline, inline first, file last resort, clean temporaries afterwards, no temporary files and no temporary folders at any moment.
. verify per stage before advancing, verify real bytes before fixing apparent corruption, analyze all failures from most recent to oldest.
. radical honesty: report real state, pendings and plan, a previous error is truly corrected, never done without proof of render or verifiable test.
. a number only gets the measured label when it comes from real execution over linked data with origin and provenance recorded, without that chain the result is declared simulated.
. shared worklog updated at each task, each agent writes its stage, a closed worklog is the done criterion.
. the session law: the checkpoints chain never stops, all merged at the end, the last edit prevails.
. nothing is downloaded and no binary is installed, dependencies come from the global node modules or the cdn imports, and the system never installs anything global.
. clone and create everything inside the work root, free space before every clone, and the heavy clones are deleted after the analysis.

## browser control

. control only the owner real logged in brave through the own computer use skill, one single pid and one port, in background, headless compatible, and never touch opera, the zai tab or any other browser or tab.
. open one new tab with ctrl n and keep the work separated and isolated in it, one tab per operation, one window reused, multiple separate windows consume memory and are forbidden, and if the owner closed the browser, open brave and proceed.
. work frame by frame from screenshots, logs and json are never the primary source of truth, the loop is capture, read, identify, understand, act, then capture again to confirm, and playwright with json plus image description is the fallback when the state is not confirmed.
. the screenshot method is the official method for confirming that a page was published, and playwright and the browser agent stay synchronized on the same page and session.
. work fast: a safe, progressive, batch pipeline, about five minutes for the whole configuration, something live inside the first five minutes, no long pauses between steps, no forgotten enter presses, click, type, press enter and move on, never re reason about what is already visible on the screen.
. map each site through devtools first, every tab, button and field, then run the batch pipeline, humanize the actions, type at a natural pace, keep waits short.
. navigate through the ui or the dom, workers are not a fallback for missing setup.
. read the explanation already printed on the interface before reasoning, the answer is usually on the screen beside an edit button, and search the internet only when the interface does not settle the question.

## language and translation

## catalog and dependencies

. the master catalog carries more than 43 thousand dependencies and no package.json carries them all, resolution explodes build memory, the lockfile never closes and the registry refuses.
. package.json carries build essentials, the full catalog is available through vfs and cdn at execution without installing, and granular install is for materialization inside the virtual sandbox, never for the build host.
. every package.json of the family comes from the single catalog, whole set, mirror overrides and pinned versions, and a new dependency enters by the catalog version.
. pins are exact, minimum release ages are respected, one lock per manifest.
