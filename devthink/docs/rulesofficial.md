# rulesofficial.md

the official rules of the devthink family operation. the owner statements are the source, session 7 prevails over the other sessions, and this file maps every rule of the owner rule file and of the session 7 owner voice, merged and deduplicated, nothing invented. the format obeys the writing rules themselves: dot hierarchy, lowercase, english, zero emoji, links only in the last paragraph.

## objective

. devthink is the superplatform, the virtual operating system of the internet: it carries every application the person needs and competes with the whole market at once, the os, the browser, the chat and the cloud.
. the chat application is the urgent item: fully functional, it opens the sandbox and executes the sandbox, sustained by saddle, with the design and the presentation icon redefined to the reference standard.
. one application works fully at a time: devthink first, then the sub apps, one at a time, never all at once.
. something is put online immediately, before anything else is finished: a plain blank white page in english on the main domain, then the policy page and the terms page.
. authentication stays on the own self hosted infrastructure, never supabase as a service, because the own infrastructure has no limits.
. later the repository builds to cloudflare, netlify, vercel and github pages and serves the full domain, so no current choice may close that path; the infrastructure is universal, deploys on any platform, and nothing is hardcoded to one host.
. the configuration of external platforms is done through the owner real logged in brave browser, because the owner cannot configure those screens and is working on another task.

## operation

. two phases only, analysis first, execution second, never mixed, a phase closes before the next opens.
. the fixed step order: delete everything, read files, create authentication, run the full analysis, create documents, execute.
. reading is linear, hierarchical, top to bottom, never skipping lines, never jumping around, in segments of line ranges via the bash terminal, sed from x to y, index first, details after, segments of 1000 to 4000 lines for giant files and smaller segments for the rest.
. the read tool is never used, by the agent or by any sub agent; the forbidden tools are read, chaos tools and results tools.
. delegation is open, from zero to 300 sub agents in parallel, any number of waves, every wave hierarchical and objective, with verification each wave.
. work in waves: 30, 40, 70 or 80 waves, each wave a selective group of changes with a commit at the end, waves contain sub waves, there is no stopping.
. every action of more than 100 steps starts with a checklist of about 100 items, organized in waves, adapted to context, and the system itself follows the same rule.
. date first: consult the date and use the best standard and version of that date at each step.
. delegate sub agents before executing inline, inline first, file last resort, clean temporaries afterwards, no temporary files and no temporary folders at any moment.
. verify per stage before advancing, verify real bytes before fixing apparent corruption, analyze all failures from most recent to oldest.
. radical honesty: report the real state, the pendings and the plan, never done without proof of render or verifiable test, a previous error is corrected for real.
. a number only carries the measured label when it comes from real execution with origin and provenance recorded, without that chain the result is declared simulated.
. the shared worklog is updated at each task, each agent writes its stage, a closed worklog is the done criterion, and the worklog never rides the repository.
. nothing is downloaded and no binary is installed, dependencies come from the global node modules or the cdn imports, and the system never installs anything global.
. clone and create everything inside the work root, free space before every clone, clone allan first and devthink after the allan analysis, and the heavy clones are deleted after the analysis.
. fetch before and after every wave because the workspace can reset, verify the commit landed, then proceed to the next wave.
. sub agents never commit, the orchestrator commits, and design agents never touch workflows, changelogs or versions.
. nothing is deleted: duplicates keep a numeric suffix, retired infrastructure is kept marked as previous plan.
