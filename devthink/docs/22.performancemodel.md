# Performance model (1.1.68)

This document describes the performance model the 1.1.68 performance part one release introduces: the lazy loading of heavy modules, the debouncing and batching of dom work, the incremental snapshots and the selector cache, the virtualized long lists, the streamed parsing of oversized pages, the chunked extraction of big tables, the worker queue backpressure and the per step perf records. Every window, depth, cadence, bound and budget in this model stays the user's choice: performance features optimize the hot paths and never cap, never refuse and never bypass the consent review.

## Layers

| Layer | Module | What it does |
| --- | --- | --- |
| Lazy loading | `lazyload.ts` | Declares the heavy modules (the parsers and the capture, compare and export families) with their load reasons and capability requirements, resolves them on first use under the same capability checks the eager path runs, prewarms the user chosen set on startup and records load telemetry for startup analysis. |
| Dom batching | `dombatch.ts` | Builds the debouncedom profiles of the user configured windows, coalesces scroll, input and resize storms per window, folds one dom observer mutation burst into one batch, and folds repeated selectors into one batchquery pass that executes as one offscreen worker task. |
| Incremental snapshots | `snapshotdelta.ts` | Fingerprints every region with a stable local hash, computes the delta of added, changed and removed regions against the base snapshot ref of the same run, returns the full snapshot on the user configured cadence and exposes the empty delta the executor skips. |
| Selector cache | `selcache.ts` | Caches selector resolutions per generation, advances the generation on every mutation batch, invalidates wholesale on navigation and selectively on matching mutation fingerprints, revalidates hits before dispatch and reports stale generation failures with a reviewed retry hint. |
| Virtualized lists | `virtlist.ts` | Keeps the visible row window with a measured height map, clamps the window inside the row range during scroll, recycles the row nodes of the overlap and reports the rendered, skipped and recycled counts. |
| Streamed parsing | `streamparse.ts` | Splits a large page into chunk windows of the user byte bound, tokenizes one chunk at a time inside the worker pool, yields observations progressively as chunks complete and never holds the full page text. |
| Chunked extraction | `streamparse.ts` | Slices a big table into resumable row windows through a cursor that carries the table fingerprint, emits each window as a partial extraction result, refuses a resume across table states and merges the windows into the datagrid without duplicates. |
| Perf records | `perfrecords.ts` | Records the duration, the query count, the cache hits, the delta flag and the provenance of every step, sums the perf summary of a run, charts the step durations, applies the worker queue backpressure, deduplicates identical snapshot requests within a run, schedules heavy captures behind the user priority choice and cancels abandoned parse tasks of a halted run. |

## The user choices

| Setting | Meaning | Absent value |
| --- | --- | --- |
| `prewarmset` | The lazymods the user warms on startup. | Every heavy module stays out of the startup path. |
| `lazybudget` | The startup module budget the view reports against. | No budget is reported and no load is ever refused. |
| `debouncewindows` | One coalescing window in milliseconds per event kind of scroll, input, resize and mutation. | Every event of the kind passes through uncoalesced. |
| `snapshotcadence` | The number of deltas between two full snapshots. | Every snapshot stays a delta against its base. |
| `workerdepth` | The worker queue depth for backpressure. | The queue runs unbounded. |
| `perfretention` | The retention window of the stored perf records. | Every record stays. |
| `virtlistrows` | The virtlist row window per surface. | Every row renders. |
| `capturepriority` | `speed` defers heavy capture work to the run end; `evidence` keeps the captures beside their steps. | The captures stay beside their steps. |

## Gates

`lazyloadgate` keeps lazy loading transparent to capability checks; `debouncewindowvalid`, `virtlistwindowvalid`, `lazybudgetvalid` and `workerbackpressuregate` validate every window, depth and budget as user choices only; `batchqueryplangate` refuses plans with unfolded duplicates; `incrsnapshotgate` requires a base snapshot ref of the same run; `selcachegate` refuses stale generation hits; `streamparsegate` runs every chunk through the same schemastrict validation the one pass parser runs; `chunkextractgate` verifies the table fingerprint on every resume; `perfprovenancegate` attaches provenance to every perf record.

## Instrumentation points

The executor instruments the hot paths without changing any consent behavior: the parse offload records a perf record with its turnaround and consults the backpressure before entering the worker pool, an empty incrsnapshot delta skips the whole recomputation, identical snapshot requests within a run answer from the request cache, the heavy capture pairs defer to the run end behind the user speed priority, a mid run revocation cancels the abandoned deferred parse tasks of the halted run, and every executed step writes its perf data and its delta change set beside its outcome in the progress record. The sidepanel run footer (query counts, cache hits, selcache generation), the stepstimeline parse durations, the popup worker queue depth, the datagrid chunk cursor progress line, the optionspage performance section and the dashboardpage perf summary with its step duration chart all read the same records — no surface keeps its own state.

## The certification suite runtime budget

The 1.1.96 multi agent certification adds the coordination suite runtime budget: the agentcert gate of `tests/agentcert.mjs` runs its thirty coordination scenario entries against the real compiled modules in the deterministic fake clock mode (no wall clock read, every fixture time from the fixed epoch), so a full suite run stays under thirty seconds on the verify runners and a regressed run that crosses the budget surfaces through the gate output rather than a silent slowdown; the costcert gate of `tests/costcert.mjs` runs its nine accounting checks the same way and stays under ten seconds. Both gates ride `pnpm validate:agents` inside `pnpm validate` and the verify workflow beside the security gates, and the artifact writes (`tests/artifacts/agentcert.json` and `tests/artifacts/costcert.json`) stay bounded by their fixed entry count with no timestamps so reruns stay byte identical. The chromium smoke runs the leader worker topology scenario end to end inside the live browser without extending the smoke budget: the scenario replays through the same fake clock and answers in the smoke pass.
